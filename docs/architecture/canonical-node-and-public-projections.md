# Canonical node and public projections

**Status: target architecture and contract.** This document records the
architecture Portaless is to implement for a private canonical node and one or
more public publishing targets. It does not claim that local/Cloudum replication,
private archives, or approval-bound publishing are fully implemented today.

## Purpose

An owner needs a private place to hold the authoritative content, revisions,
drafts, personal archive and credentials, while publishing a deliberately
filtered set of material to Git-based hosts such as GitHub Pages or Cloudflare
Pages. The public host is a projection, not the place where private state or
provider credentials live.

This implements the direction in [`VISION.md`](../VISION.md): one canon, many
projections. It is also the architectural contract for the local-node and
Cloudum-hosted-node modes.

## Terms

| Term | Contract |
|---|---|
| **Canonical node** | The one active writer for a site's content, publication state, private archive, permissions and credentials. It may run on the owner's computer or in a private Cloudum Docker deployment. |
| **Public projection** | A generated, allowlisted snapshot containing only explicitly approved public revisions and their public metadata. It can be built for GitHub Pages, Cloudflare Pages or another compatible Git publisher. |
| **Private archive** | Personal material such as `.airchive/`, future drafts and private documentation. It is not part of a public build or public Git repository. |
| **Secret** | Credential or private key used to authenticate, sign or decrypt. It is not content and must never be included in an AI context or public projection. |
| **Active writer** | The canonical node currently allowed to accept edits. A backup or restored copy must not become a concurrent writer without an explicit handover. |

## Trust boundaries and flow

```text
Owner and authorized AI client
             │ authenticated, capability-scoped requests
             ▼
┌──────────────────────────────────────────────────────┐
│ Private canonical node                               │
│ Local Docker/Node OR private Cloudum Docker           │
│ content · revisions · drafts · private archive       │
│ permissions · credentials · MCP · admin              │
└──────────────────────┬───────────────────────────────┘
                       │ explicit approval + allowlisted export
                       ▼
┌──────────────────────────────────────────────────────┐
│ Public projection repository / publication artifact  │
│ approved public pages · public revision evidence      │
│ no private archive · no drafts · no credentials       │
└──────────────────────┬───────────────────────────────┘
                       ▼
 GitHub Pages / Cloudflare Pages / compatible publisher
```

### Canonical-state rules

1. A site has one active canonical writer at a time. The local and Cloudum
   modes are alternative locations for that node, not independent writable
   replicas.
2. The canonical node owns content and publication state. Public Git history is
   the history of public projections; it is not a backup of the private node.
3. A public projection is generated from an allowlist and a specific approved
   revision. It must not be generated by copying a mixed private working tree.
4. Publishing a revision does not turn its private source material into public
   material. Once published, however, a public revision must be assumed
   downloadable and retainable by third parties even if later removed.
5. Git commit history is evidence of repository history, not by itself proof of
   authorship, truth, reputation or immutable storage. A public claim about a
   revision must identify the content hash/revision and the evidence and rules
   used to evaluate it.
6. A reputation observation is bound to the exact public revision it evaluated.
   A new revision does not overwrite the old observation. The UI must show the
   observation time, source, sample size/weight where applicable, and the
   scoring-rule version. No causal claim is made unless the evidence supports it.

## Public history and reputation

The public publishing target may keep Git commits for the approved public
projection. To make history portable across publishers and available on the
site's own domain, the target design is a public revision manifest containing
stable publication ID, public revision/content hash, publication time, parent
revision where known, and links to verifiable evidence. It must not expose the
private canonical repository, `.git` directory, drafts, private documents,
credential values, or private commit messages.

If the owner wants to show that one revision was evaluated at 4.6 and a later
revision at 4.1, Portaless must retain two separate observations tied to two
different revision hashes. The score alone is insufficient: Portaless must
show the input evidence and scoring version, and say “no data” when it has no
evidence. A commit diff can show what changed; it cannot prove that the change
caused a reputation change.

The public revision manifest and its verifier are **not yet established by this
document**. Their wire format, signing model, retention policy and compatibility
with APW are implementation decisions to make in the revision-history phase.

## Local and Cloudum modes

| Mode | Canonical node | Public projection | Backup |
|---|---|---|---|
| Local | Owner-operated Node/Docker on the owner's machine | Git-based public target | Optional encrypted/off-device backup; owner controls availability |
| Cloudum private node | Private Docker deployment operated for the owner, reachable only through configured private access | Same Git-based public target | Optional restore copy to the owner's computer |

The Cloudum product is an external deployment/operations offering, not a
Portaless Core dependency. Tailscale/private networking can restrict network
reachability; it does not by itself prove that a host operator cannot access a
mounted volume. The service threat model, operator access, encryption-key
custody, backups and recovery guarantees must be stated by the service provider.

### Handover and restore

Moving the canonical node from local to Cloudum or back is a controlled
handover:

1. Stop writes on the old active node.
2. Create and verify a backup of canonical data and its revision metadata.
3. Restore into the target node and verify schema, content hashes and secret
   availability without exporting secret values into logs.
4. Explicitly activate the target as the sole writer.
5. Verify that its next public projection is derived from the expected revision.
6. Keep the old copy read-only or offline until rollback is no longer needed.

Automatic multi-writer synchronization and conflict resolution are out of
scope. The optional personal-computer copy is a backup/restore target, not a
second simultaneous canonical writer.

## Current implementation boundary

Verified in the repository at the time of writing:

- `scripts/publish-site.mjs` reads a self-hosted SQLite `PageStore`, writes
  publishable layouts under `src/content/pages/`, runs `npm run build`, and
  publishes the `dist/` files through the GitHub API. It requires a terminal,
  SQLite and configured GitHub credentials; C08 still needs a clean staging
  exporter and stale-artifact removal.
- `packages/deploy-engine/src/draft-filter.ts::isPubliclyPublishable()` is the
  central public-projection policy used by static content routes, listings,
  feeds, sitemaps, `llms.txt`, the Node page route and the publish CLI. It
  excludes draft, private, legacy `-draft` and unknown states; layouts with no
  status retain the legacy published behavior.
- The Node dynamic public page route now returns a generic 404 `no-store` for a
  database draft/private row and does not fall through to stale static HTML.
- MCP `create_page` always creates drafts; MCP/plugin content reads omit
  non-public pages, and writes cannot publish or modify public/private pages.
  Authenticated admin UI is the explicit publication/privatization control.
- GitHub Pages serves static output and does not execute Portaless Functions.
- `packages/mcp-server/` is a separate Node process. Its HTTP transport binds
  to loopback by default; it is not an HTTP endpoint automatically supplied by
  GitHub Pages or Cloudflare Pages.
- `.gitignore` excludes `.airchive/`, but this alone is not a public-export,
  Docker-image or endpoint confidentiality guarantee. C09 still needs to
  exclude private paths from container/distribution build contexts.

Remaining work: C07 must add an authenticated private preview that cannot
fallback to public bytes; C08 must build a clean allowlisted projection and
remove stale published artifacts; C09 must harden packaging. These requirements
are not complete until their tests prove that a synthetic private marker is
absent from every public surface and artifact.

## Non-goals for this contract

- Publishing the private Git repository or exposing its `.git` directory.
- Treating Git history as tamper-proof, signed authorship or proof of truth.
- Automatically forwarding every private document to a hosted AI model.
- Running two writable canonical nodes and resolving conflicts after the fact.
- Making GitHub Pages execute admin, database, MCP or private-node workloads.
