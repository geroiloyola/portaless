## Verdict and scope

**Qualified result, not an unconditional approval.** The tested local paths pass
after the corrections in this working tree. The repository still has an
unprotected `main` branch, a mobile-header contract discrepancy, and a partially
shared shell implementation. Docker, live D1, a production mail relay and a
full historical secret scan were not executable here.

Baseline: `d203969` on `hardening/c19-c22-mobile-ui`. This audit reviews the
integrated tree, not isolated checkouts/builds of every historical commit. The
new corrections are uncommitted. No repository rules, deployments, production
data or signing formats were changed.

## Corrected findings

1. **C08 — missing documentation routes.** The path-component deny filter
   rejected `src/pages/docs/` as if it were a private documentation directory.
   The clean static projection built without Docs. The narrow route exception
   now retains public route code while keeping canonical docs curated. The
   export smoke asserts `/docs/first-steps/index.html` exists.
2. **C08/C24 — unfiltered history trees.** `src/content/revision-history/` and
   `public/revisions/` could be copied wholesale from the node. Both are now
   excluded from copying and generated only from approved store rows. Synthetic
   private markers in both locations are included in the export smoke.
3. **C11/C23 — invalid D1 migration files.** New revision/evidence statements
   lacked trailing semicolons and were joined by newlines. The file serializer
   now terminates every statement; regression executes the generated SQL with
   actual SQLite parsing, including triggers.
4. **C06/C23/C24 — divergent privacy policy.** Revision approval checked only
   `status`/legacy slug, ignoring `draft` and `visibility`. Adoption, writes and
   import/project checks now reuse `isPubliclyPublishable()`.
5. **C23 — client-supplied publication IDs.** Ordinary creation trusted
   `layout.publicationId`; it could be malformed or collide, and became a file
   path during export. Creation now assigns server-owned IDs; original IDs enter
   only through the validated transfer importer.
6. **C23/C24 — recreated slug history mixing.** Slug-based history queries
   merged distinct publications after delete/recreate. They now resolve the
   current publication ID; explicit publication-ID history remains separate.
7. **C23 — D1 simultaneous create failure.** Concurrent creation could throw a
   raw unique-constraint exception. Conditional insertion now yields
   `revision_conflict`, with no losing revision inserted. Real-SQL adapter tests
   cover concurrent creation and stale updates on both backends.
8. **C06/C23 — repeated plugin draft edits failed.** Plugins cannot read drafts,
   but their second draft write now needed a revision token. The bridge uses its
   own policy-checked read as the write precondition, preserving the owner-write
   race barrier. This permits repeated draft edits without granting draft reads.
9. **C23 — editor save/undo lost the persisted token.** The editor ignored the
   metadata returned by PageStore. It now tracks the persisted token separately
   from undo snapshots; the HTTP store returns revision metadata too.
10. **C23/C24 — hash contract and metadata exposure.** The hash included status
    despite documentation saying otherwise; exported layouts copied unknown
    top-level fields. Hash/export now use the explicit authored-content
    allowlist, including nested element props but excluding lifecycle/private
    top-level metadata. This corrects the unreleased format; pre-audit hashes
    that included status are not silently rewritten or accepted as the new hash.
11. **C24 — arbitrary 100-revision transfer limit.** A node could export a
    history it could not import. The count cap was removed; the HTTP byte ceiling
    remains. A 101-revision transfer is exercised against the real-SQL adapter.
12. **C24 — publication/history snapshot mismatch.** The publisher could load a
    page, then export a newer history after a concurrent edit. History export is
    now pinned to the already selected page head and validates IDs/hashes before
    writing paths.
13. **C24 — static-history fallback and validation.** A deployment without a DB
    now delegates to its generated history asset. Configured-store history
    validates the portable record/hashes before serving it; it does not claim
    success with inconsistent hashes.
14. **C24 — import body bound.** The importer formerly allocated the entire
    body before checking its own ceiling. It now uses the shared bounded stream
    reader and returns 413 without reading an oversized declared body.
15. **C24/C25 — N+1 D1 evidence queries.** History fetched evidence once per
    revision, consuming per-request query budgets. D1 now reads evidence with a
    single publication-scoped join.
16. **C16 — stalled STARTTLS handshake.** The deadline destroyed the old socket
    while the handshake promise only listened for secureConnect/error. It now
    owns the secured socket immediately and rejects on premature close. A relay
    that accepts STARTTLS but never completes TLS is covered by a real TCP
    fixture with a shortened test deadline.
17. **C19/C22/C26 — UI details.** Docs navigation/Markdown controls now have
    44px targets; history code blocks scroll locally. A later revision with no
    content changes no longer says it is the first public revision.
18. **C05 — browser regressions absent from CI.** Chromium installation and the
    browser suite are now explicit steps in `ci.yml`. Their Ubuntu execution
    remains to be confirmed by a subsequent CI run.

## Open findings and verification limits

- **High, C05:** GitHub API returned `Branch not protected` for classic
  protection and `[]` for effective rules on `main`. PR-only/manual approval
  currently depends on convention. Owner configuration is required; the audit
  did not change permissions or rules.
- **Medium, C20:** `acceptance-contract.md` §6 requires all selected mobile
  header controls on one row and moves Trust/context controls to the page or
  footer. `global.css` currently stacks nav and `.header-right`; the browser
  tests explicitly validate that alternative. Passing those tests is not
  acceptance of the stricter contract.
- **Medium, C21:** shared header rendering is real, but the footer and inline
  fallback CSS in `functions/pages/[slug].js` are still separately maintained
  from Astro. Full-shell deduplication was overstated as complete.
- **C25/C26:** no real revision-specific reputation provider/verifier exists.
  Imported `proof` is stored provenance, not verified cryptography. Empty data
  stays `no_data`; these tests do not establish signed authorship or causality.
- **C26:** UI exposes the timeline and changed JSON paths, with full snapshots
  in the manifest. A dedicated historical rendered-page/before-after viewer
  would be additional work if required for final acceptance.
- Docker and Gitleaks binaries are absent locally. Image/runtime isolation and
  a full historical credential scan were not rerun. The workflow definitions
  were reviewed; this is not a claim that their remote jobs passed.
- D1 adapter tests execute actual SQL and transactions over SQLite. They do not
  certify Cloudflare bindings, account quotas or the remote Wrangler import path.
- Real mail delivery, Cloudum handover, ChatGPT account compatibility and the
  20 GB / 2 GiB resource budget remain outside the evidence of this local run.
