## V-01 — Fingerprint `k` (RFC 7638)

Input: only the mandatory members of the Ed25519 JWK, in lexicographic order, no whitespace:

```
{"crv":"Ed25519","kty":"OKP","x":"<x>"}
```

Output: `base64url(SHA-256(<json>))` unpadded, 43 characters.

| # | Key | `x` | Expected fingerprint |
|---|---|---|---|
| 1 | RFC 8037, Appendix A | `11qYAYKxCrfVS_7TyWQHOg7hcvPapiMlrwIaaPcHURo` | `kPrK_qmxVWaYVA9wwBF6Iuo3vVzz7TxHCTwXBygrS4k` |
| 2 | RFC 9421, Appendix B.1.4 | `JrQLj5P_89iXES9-vFgrIy29clF9CC_oPPsw3c5D0bs` | `poqkLGiymh_W0uP6PZFw-dvez3QJT5SolqXBCW38r0U` |

Rejection rules:

- JWK without a supported `kty` (other than `OKP`) → error `unsupported_key_type`.
- `OKP`/`Ed25519` JWK without `x` → error `missing_jwk_member:x`.
- Optional and private members (`d`, `key_ops`, `ext`, `kid`, `alg`) are **ignored** when computing: vector 1 must still yield the same fingerprint even if they are added.

## V-02 — Key identifiers

With `did = did:apw:example.com`:

| Expression | Expected value |
|---|---|
| `keyId(did, 1)` | `did:apw:example.com#key-1` |
| `keyId(did, 12)` | `did:apw:example.com#key-12` |
| `parse(keyId(did, 12))` | `{ did, sequence: 12 }` |
| `keySequence` of a site's first key | `1` |
| After two rotations | sequences `1, 2, 3`; only the last with `validTo: null` |
| `fingerprint` published in `keys[].kid` | equal to `fingerprint` (alias) |

Rejections when constructing: `did` that is not `did:apw:<domain>` (`invalid_did`); sequence 0, negative, or non-integer (`invalid_key_sequence`).

Rejections when parsing (returns null): `#key-0`, `#key-01` (leading zeros), `#key-` without a number, a DID without a fragment, a `did:web:` with the same pattern, a 43-character base64url fingerprint without `#key-<n>`, and any non-string.

Key-list invariants (otherwise `key_kid_mismatch`):

- Each key's `kid` = the RFC 7638 fingerprint of its `publicKeyJwk`.
- No repeated `keyId`; no `keyId` equal to another key's fingerprint.
- Every `keyId` has `did` equal to the site's DID and a unique `<n>`.

## V-03 — TXT manifest

Serialization: compact JSON (no spaces), optional fields omitted.

| # | Input | Result |
|---|---|---|
| 1 | `{siteId:"s", contentKinds:["mixed"]}` without `k`/`h`/`rg` | v1: `{"v":1,"siteId":"s","trustUrl":"/trust/s","contentKinds":["mixed"]}` |
| 2 | the same with `k` | v2: same payload with `"v":2` and the `k` field |
| 3 | `v:2, k:"short"` | reject `invalid_key_fingerprint` |
| 4 | `v:2, h:5` (not a string) | reject `invalid_history_head` |
| 5 | `v:2, rg:"yes"` (not a boolean) | reject `invalid_read_governance` |
| 6 | `v:1` with `k` present | valid as v1; `k` is **ignored** (no verifiable identity) |
| 7 | `contentKinds: []` | reject `empty_contentKinds` |
| 8 | `contentKinds: ["pdf"]` | reject `invalid_contentKind_value` (closed vocabulary: `text`, `image`, `product`, `link`, `mixed`) |
| 9 | `trustUrl` without the `/trust/` prefix | reject `missing_or_invalid_trustUrl` |
| 10 | Broken JSON or a scalar | reject `not_an_object` |
| 11 | `v:3` | reject `missing_or_invalid_version` |

Accepted formats for `k` and `h`: `/^[A-Za-z0-9_-]{43}$/`. Example of a complete v2 manifest:

```
{"v":2,"siteId":"example.com","trustUrl":"/trust/example.com","contentKinds":["mixed"],"k":"kPrK_qmxVWaYVA9wwBF6Iuo3vVzz7TxHCTwXBygrS4k","h":"AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA","rg":true}
```

Cross resolution `TXT` + `did.json` (expected reasons):

| Situation | Reason |
|---|---|
| `did.json` fingerprint == `k` and `id` == `did:apw:<domain>` | `ok`, `verified: true` |
| fingerprint different from `k` | `key_mismatch` |
| `did.json` from another domain | `did_mismatch` |
| manifest without `k` (single DNS lookup; `did.json` is not fetched) | `manifest_without_key` |
| `did.json` unreachable | `did_document_unreachable` |
| `did.json` without a valid DID structure | `invalid_did_document` |
| site with no registered identity | `404 site_identity_not_found` |

The public `did.json` **never** includes private members or `d`; only the public key in `verificationMethod[0].publicKeyJwk` with exactly `crv`, `kty`, `x`.

| # | Input | Output |
|---|---|---|
| 1 | `{ b: 1, a: [true, null, "x"], c: { z: 1, y: 2 } }` | `{"a":[true,null,"x"],"b":1,"c":{"y":2,"z":1}}` |
| 2 | `{ n: -0 }` | `{"n":0}` |
| 3 | `[1e21, 1.5, 100]` | `[1e+21,1.5,100]` |
| 4 | `{ s: "ñ€" }` | `{"s":"ñ€"}` (unicode unescaped) |

Issuer rejections (error `not_i_json`): `undefined`, `NaN`, `Infinity`, functions, `bigint`, `Date`. The issuer rejects rather than omits or coerces.

## V-05 — History hash and chain

Normative hash: `base64url(SHA-256(<bytes>))` unpadded (43 chars).

| # | Input (utf-8) | Expected hash |
|---|---|---|
| 1 | empty string | `47DEQpj8HBSa-_TImW-5JCeuQeRkm5NMpJWZG3hSuFU` |
| 2 | `att-1` | `IIZMRjHGtF_r1Jv8RZNnxpJ2s-xVBZoz-BkR8IWH9Ik` |
| 3 | 43 characters of `A` | `DwBzhbb51LfusnSGBa_hqYSgo7-j8BTQnip4TOnlzRo` |

Log entry structure:

- JWS header: `{"alg":"EdDSA","kid":"did:apw:<domain>#key-<n>","typ":"apw-log+jws"}` (or `kid` = fingerprint in entries predating the `keyId` definition; both are accepted).
- Payload: `{"seq":1,"prev":null,"att":"<43-char hash>","ts":"<ISO 8601 UTC>"}`.
- `seq` grows by 1; entry `n`'s `prev` = `hash(jws of n-1)`; the TXT's `h` = the `hash` of some entry.

Pagination of `GET /.well-known/apw-log.json`: `?from=<seq>&limit=<n>`, `limit` maximum 500; response `{ did, head: { seq, hash }, length, keys, entries: [{ seq, jws }], next }`, where `next` is the next `seq` or `null`. Without identity: `404`. `keys[i]` exposes only the JWK's public members (`crv`, `kty`, `x`).

Chain rejection matrix:

| Mutation | Expected reason |
|---|---|
| an entry's payload replaced by another | `bad_signature` at that `seq` |
| an entry removed | `seq_gap` |
| `prev` that is not the previous entry's hash | `prev_mismatch` |
| `ts` earlier than the previous entry's | `ts_regression` |
| `ts` outside its key's `validFrom`/`validTo` window | `ts_outside_key_window` |
| an entry's `kid` not published in `keys` | `unknown_key` |
| `kid` from another domain or malformed | `key_kid_mismatch` |
| TXT `k` != the log's active key | `active_key_mismatch` |
| TXT `h` that does not appear in the chain | `head_mismatch` |
| empty chain with a published `h` | `head_mismatch` |
| empty chain without `h` | valid (`length: 0`, `head: null`) |

Anchoring: if the TXT's `h` corresponds to entry `s`, the chain verifies with `anchoredSeq = s` and `unanchoredEntries = length - s`; an `h` equal to the last entry gives `unanchoredEntries = 0`. Rotating the key does not invalidate the past: the chain verifies with the new active key, and fails with `active_key_mismatch` if the retired key is required.

## V-06 — Foreign-issuer attestations

Typical payload (`agent` about a site, with `iss` = the agent's https origin):

```json
{"typ":"apw-attestation+jws","iss":"https://agent.example","sub":"did:apw:example.com","src":"agent","cat":"https_and_headers","val":true,"iat":1790000000,"jti":"agt-2026-10-abc"}
```

The receiver verifies the bytes **exactly as received** (no canonicalization). Validation order and first failure:

| Step | Condition | Failure |
|---|---|---|
| 1 | 3-part compact JWS, <= 8192 chars | `malformed_attestation` |
| 2 | header/payload decode to objects | `malformed_attestation` |
| 3 | `header.alg == "EdDSA"` | `unsupported_alg` |
| 4 | `header.typ` absent or `apw-attestation+jws`; `payload.typ == "apw-attestation+jws"` | `invalid_typ` |
| 5 | `header.kid` == the expected one, when required | `kid_mismatch` |
| 6 | key `kty: OKP`, `crv: Ed25519`, `x` a string (not ML-DSA) | `unsupported_key` |
| 7 | valid Ed25519 signature over `header.payload` | `bad_signature` |
| 8 | claims: `iss`/`sub`/`src`/`cat`/`jti` strings, `cat` of 1..64, `val` boolean, `iat` a safe integer, `jti` in `[\x21-\x7e]{1,128}` | `invalid_claims` |
| 9 | `sub == did:apw:<siteId>` | `sub_mismatch` |
| 10 | `src` == the endpoint's source | `src_mismatch` |
| 11 | `iss` equal to the expected one (https URLs by **origin**) | `iss_mismatch` |
| 12 | `abs(now - iat) <= 300` s, unless `skipIatWindow` | `iat_out_of_window` |

https `iss` cases: `https://agent.example/p` and `https://agent.example/other` are the same issuer; `http://agent.example` or `https://sub.agent.example` are not.

`jti` unique per issuer: repeating an accepted `jti` → `409 duplicate_attestation`. Flat body fields different from the signed payload → `400 attestation_mismatch`. Escrow provider without `public_key_jwk` → `403 provider_without_public_key`. If history anchoring fails but the report is stored → response with `logged: false`.

`reader_conduct` read from a third party's history: same order, but with `skipIatWindow` active and the key required to be the issuer's active one (its TXT `k`); any failure leaves the reader `apw_unresolvable`.

## V-07 — Site-signed JWS

Exact header: `{"alg":"EdDSA","kid":"did:apw:<domain>#key-<n>","typ":"<typ>"}`. Payload in strict JCS form.

Extended manifest (`typ: apw-manifest+jws`, `GET /.well-known/apw-manifest.jws`, `application/jose`): payload = TXT fields + `did` + `iat`:

```json
{"did":"did:apw:default","h":"aaaa…(43)","iat":1790000000,"k":"aaaa…(43)","rg":true,"siteId":"default","trustUrl":"/trust/default","contentKinds":["text"],"v":2}
```

That object, canonicalized, must reproduce the payload bytes exactly. `self` uses `typ: apw-attestation+jws`, `iss = sub = did:apw:<domain>`, and is verified with the V-06 routine requiring `kid`.

Mutations and results:

| Mutation | Result |
|---|---|
| altered byte in the signature | `bad_signature` |
| `kid` = `#key-2` when `#key-1` is required | `kid_mismatch` |
| `typ` different from the expected | `invalid_typ` |
| signature made with another rotation's key | `bad_signature` |
| non-JCS payload (bytes that are not `JCS(JSON.parse(payload))`) | `not_canonical` |
| `kid` that is not `did:apw:<domain>#key-<n>` when signing | error `invalid_key_id` |
| another DID's `kid` when signing `self` | error `key_id_not_for_did` |
| no registered identity | `404 site_identity_not_found` |

## V-08 — Scoring primitives

Emitter weight, `w(J) = ((clamp(J,1,7) - 1) / 6)^2`:

| J | w |
|---|---|
| 1.0 | 0.0 (exact) |
| 4.0 | 0.25 (exact) |
| 5.0 | 0.444444… (= 4/9) |
| 6.0 | 0.694444… (= 25/36) |
| 6.7 | 0.9025 (exact) |
| 7.0 | 1.0 (exact) |

Ratio: `w(6.7) / w(4) = 3.61`.

J from mean deviation `d`, `J = max(1, 7 - 1.5 d)`:

| d | J |
|---|---|
| no comparable attestations (`null`) | 4.0 |
| 0 | 7.0 |
| 2 | 4.0 |
| 10 | 1.0 |

Value mapping `v` (A.4.1): boolean `true`→7.0, `false`→1.0; `community` 1→1.0, 2→2.5, 3→4.0, 4→5.5, 5→7.0; outside 1..5 → error. `reader_conduct`: `respected_policy`/`rate_respected`/`paid_as_agreed` with `val:true` → 7.0 to their R dimension; `policy_violation` with `val:true` → 1.0 to R-01; `redistribution` with `val:true` → 1.0 to R-04.

`self` weight: always 0.25, whatever the site's J, and it never feeds its own R-05.

## V-09 — Bayesian score

`S = (3 * 4.0 + sum(w_i v_i)) / (3 + sum(w_i))`.

| # | Set | Expected S | Weight sum |
|---|---|---|---|
| 1 | no attestations | 4.0000 | 0 |
| 2 | 10 × (w(6)=0.694444…, v=7.0) | 6.0950 | 6.944444… |
| 3 | case 2 + 1 × (w(4)=0.25, v=1.0) | 5.9700 | 7.194444… |
| 4 | 10 × (w(5)=0.444444…, v=4.0) | 4.0000 | 4.444444… |
| 5 | case 4 + 1 × (w(6.7)=0.9025, v=3.0) | 3.8919 | 5.346944… |
| 6 | case 4 + 1 × (w(6.7)=0.9025, v=1.0) | 3.6756 | 5.346944… |

Variations: case 3 vs case 2 = −2.05 %; case 6 vs case 4 = −8.11 %.

## V-10 — R-05 calibration (leave-one-out, 8 rounds)

Each round: consensus of the other emitters on the same (subject, dimension) **without the prior P**, mean absolute deviation `d`, `J = max(1, 7 - 1.5 d)`; all start at J = 4.0.

**Scenario S1** — 4 honest emitters (`h1`..`h4`) score 6.5 and one attacker scores 1.0, over 4 subjects (`s1`..`s4`) in W-10:

| Emitter | Expected J |
|---|---|
| h1, h2, h3, h4 | 7.0 |
| attacker | 1.0 |

Resulting weights: honest w = 1.0, attacker w = 0.0 (its attack stops moving the score).

**Scenario S2** — `h1`,`h2` = 4.5; `h3`,`h4` = 3.5; attacker = 7.0, over the same 4 subjects:

| Emitter | Expected J |
|---|---|
| h1, h2 | 6.2019 |
| h3, h4 | 5.8229 |
| attacker | 2.5570 |

Invariants: `self` and an issuer's attestations about itself do not appear in the judges map; a published R-05 dimension counts its emitted attestations (not `self`) and its `weightSum` = the count of those attestations; without prior calibration, R-05 = 4.0 with `weightSum` 0.

## V-11 — Read policy and visibility

Default policy (governed level): `require.identity = "apw_verified"`, R-01 `{min: 5.0, min_weight: 2.0}`, R-05 `{min: 5.0, min_weight: 2.0}`, `on_fail: "403"`. Governable resource: `/trust/*` (also `/trust/:siteId`). Action: `read` only. Known dimensions: W-01..W-10 and R-01..R-05.

| # | Reader | Policy | Decision |
|---|---|---|---|
| 1 | anonymous (no Web Bot Auth) | default | deny, status `401`, reason `web_bot_auth_required` |
| 2 | valid Web Bot Auth, no APW | default | deny, status `on_fail` (403), reason `apw_identity_required` |
| 3 | APW unresolvable (`timeout`) | default | deny, status `on_fail`, reason `history_unresolvable` |
| 4 | APW verified, no dimensions (all 4.0) | default | deny, `failed: ["R-01","R-05"]` |
| 5 | APW verified, R-01 {5.6, weight 3}, R-05 {5.2, weight 6} | default | **allow** |
| 6 | APW verified, R-01 {6.5, weight 0.5}, R-05 {5.2, weight 6} | default | deny, `failed: ["R-01"]` (a high score with little weight is not enough) |
| 7 | any | policy with an unknown dimension or `min` outside 1..7 | deny `403`, reason `policy_invalid` |

While R-05 is disabled (`policyDimensions`), the effective policy requires only R-01: the same cases 4, 5 and 6 evaluated against R-01 alone.

SiteTrustScore projection (A.6): always as a `projection` object = `{ dimensions, aggregates, governed }`.

- Public W set always: `W-01, W-04, W-06, W-07, W-09`. Governed by default: `W-02, W-03, W-05, W-08, W-10` and all R dimensions.
- With a denied reader: `projection` goes in `public` (`public.projection`), `dimensions` = only the public set plus the owner's explicit override if any; `aggregates` = score, count and weight sum of **all** dimensions with data; `governed: "withheld"`.
- **Owner override** (`public_overrides`, A.6): with `["W-10"]` stored and a denied reader, `public.projection.dimensions` carries the public set **plus** W-10 with its score, while the rest of the governed level (W-02, W-05…) stays hidden. The override does not change the policy: the reader remains denied. Governed dimensions only: `["W-01"]` (already public) or an unknown one rejects the save; the row is stored sorted and deduplicated, and a corrupt value in the database is ignored.
- With an allowed reader, or no active policy: `projection` in the body, `dimensions` = all; `governed: "granted"`.
- A dimension with no attestations appears in neither `dimensions` nor `aggregates` (no data is not 4.0).
- The public level can never be hidden by policy.

Cache and errors: result keyed by (host, fingerprint); 5 min on success, 60 s on failure. Unreadable policy table → `503` on `GET /trust/:siteId`. No resolution error ever opens the resource.

## V-12 — `reader_conduct`

Category-to-dimension mapping (besides V-08): `respected_policy`→R-01, `policy_violation`→R-01 (inverse), `rate_respected`→R-02, `paid_as_agreed`→R-03, `redistribution`→R-04 (inverse). Unknown category → error.

Reference implementation defaults (adjustable, but these are the defaults):

| Key | Value |
|---|---|
| `emissionPeriod` | `month` |
| `policyDimensions` | `{"R-01": true, "R-05": false}` |
| `maxAttestationsLoaded` | `200` |
| `legacyEntriesWithoutJws` | `ignore` |
| `legacyCutoff` | `2026-10-04T00:00:00.000Z` |

Deterministic emission `jti`: `rc-` + `base64url(SHA-256("<issuerDid>|<readerDid>|<period>|<cat>"))` unpadded. UTC period key: month `YYYY-MM`, day `YYYY-MM-DD`, ISO week `YYYY-Www`. Repeating a period's emission returns the existing `jti`s as `already_emitted` instead of duplicating.

Ledger emission rules (defaults): `policy_violation` with `val: true` if `policyViolationsDetected > 0`; `respected_policy` with `val: true` if `requestsTotal > 0` and `policyViolationsDetected == 0`. Emission only if the requester's `operatorKeyId` is the reader's TXT `k`.

Completeness when loading a reader's history:

| Situation | Result |
|---|---|
| every chain entry has its JWS and every JWS has its hash in the chain | valid load |
| JWS whose hash is not in the chain | dropped (cannot be invented) |
| entry without JWS with `ts` >= `legacyCutoff` | completeness broken → `apw_unresolvable` |
| entry without JWS with `ts` before the cutoff, `legacyEntriesWithoutJws = "ignore"` | ignored |
| entry without JWS with `ts` before the cutoff, `legacyEntriesWithoutJws = "reject"` | `apw_unresolvable` |
| `reader_conduct` that does not verify against the issuer's keys | `apw_unresolvable` (the reader cannot discard its negatives) |
| `reader_conduct` whose issuer is the reader itself | excluded from the reader's reputation |

Explicit limit: completeness proves the reader did not hide attestations **already logged**; it does not prove origin omission nor *equivocation* (different chains to different visitors).

## V-13 — Witnesses (E-10, section 5.7)

Witness statement: compact JWS, header `{ "alg": "EdDSA", "kid": "<witness DID>#key-<n>", "typ": "apw-witness+jws" }`, payload in JCS:

```json
{ "typ": "apw-witness+jws", "iss": "did:apw:witness.example", "sub": "did:apw:subject.example", "seq": 3, "head": "<43 chars>", "ts": "2026-10-09T12:00:00.000Z", "jti": "wt-<43 chars>" }
```

Deterministic `jti`: `wt-` + `base64url(SHA-256("<iss>|<sub>|<seq>|<head|''>"))` unpadded. With `seq = 0` and `head = null`, the preimage ends in an empty `|` (`...|0|`).

Preimage examples (verify against your own SHA-256):

| iss | sub | seq | head | Preimage |
|---|---|---|---|---|
| `did:apw:witness.example` | `did:apw:subject.example` | `0` | `null` | `did:apw:witness.example\|did:apw:subject.example\|0\|` |
| `did:apw:witness.example` | `did:apw:subject.example` | `3` | `AAAA...` (43 chars) | `did:apw:witness.example\|did:apw:subject.example\|3\|AAAA...` |

Payload validation rules (besides signature and JCS, same as V-07):

| Situation | Result |
|---|---|
| `seq > 0` and `head = null` | invalid |
| `seq = 0` and `head` with a hash | invalid |
| `head` not in 43-character base64url form | invalid |
| `jti` different from the recomputed one | `jti_mismatch` |
| `iss` != the header's kid (the witness's DID) | invalid / `iss_mismatch` |
| statement not logged in a verified chain of the witness | does not count as an observation |

Evaluation: an anchored observation = `(witnessDid, seq, head, anchoredTs)`, where `anchoredTs` is the `ts` of the WITNESS's history entry containing the statement. The subject's current chain = `[(seq, hash, ts), ...]` already verified (V-05). Backdating margin: 300 s.

| # | Observations | Subject's current chain | Expected findings |
|---|---|---|---|
| 1 | `(witness, 1, H1, 12:00)` | `[(1, H1, 11:00), (2, H2, 13:00)]` | none (`ok`) |
| 2 | `(witness, 1, H1, 12:00)` | `[(1, H9, 11:00)]` | `head_mismatch` seq 1: observed H1, current H9 |
| 3 | `(witness, 2, H2, 12:00)` | `[]` | `head_mismatch` seq 2: observed H2, current `null` (truncation) |
| 4 | `(witnessA, 1, H1, 12:00)`, `(witnessB, 1, H9, 12:30)` | `[(1, H1, 11:00)]` | `equivocation` seq 1 (H1 vs H9) + `head_mismatch` from observation B |
| 5 | `(witness, 1, H1, 12:00)` | `[(1, H1, 11:00), (2, H2, 11:54:00)]` | `backdated_entry` seq 2: entry ts 11:54 vs observed 12:00 (> 300 s) |
| 6 | `(witness, 1, H1, 12:00)` | `[(1, H1, 11:00), (2, H2, 11:58:00)]` | none (11:58 is within the 300 s margin) |
| 7 | `(witness, 0, null, 12:00)` | `[(1, H1, 10:00)]` | `backdated_entry` seq 1: the chain was empty at 12:00 and the entry declares 10:00 |
